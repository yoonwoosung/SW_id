# ADR-0003: 한국관광공사(KTO) 조회 결과를 파일 캐시로 저장한다

- 상태: 승인
- 결정 시점: 2026-09-13 (커밋 `fad523ca` perf(tour): KTO 조회 결과 파일 캐시 — 일일 한도 소진 방지)
- 문서 작성일: 2026-11-09 (커밋 메시지 본문과 모듈 주석을 ADR 형식으로 옮김)
- 작성자: 윤우성
- 관련 코드: `services/tour_cache.py`, `external/tour_api.py`, `tests/test_tour_cache.py`, `common/constants.py`(TTL·최대 엔트리)

## 상황

AI 추천 페이지가 코스 카드마다 `/api/experiences/<id>/course`를 호출하고, 그 한 번이 KTO를 2~4회 호출한다. KTO 개발계정 일일 한도는 1,000건이라 시연 몇 번이면 소진된다. 한도가 소진되면 코스가 빈 채로 나온다. 공모전 심사(9/21) 전에 해결해야 했다.

## 결정 기준

- 실제로 한도 소진을 막는가 (워커가 여러 개인 서버에서도)
- 동시 작업 중인 팀원 코드(모델·마이그레이션)를 건드리지 않는가
- 캐시가 깨져도 서비스가 멈추지 않는가
- 캐시 때문에 코스 정확도가 떨어지지 않는가

## 검토한 대안

### 대안 1 — 프로세스 메모리 캐시 (dict / lru_cache)

- 장점: 구현이 가장 쉽다
- 단점: PythonAnywhere는 워커 프로세스를 여러 개 띄운다. 메모리 캐시는 워커마다 따로 쌓여 효과가 워커 수만큼 나뉘고, 재시작하면 사라진다

### 대안 2 — DB 테이블 캐시

- 장점: 영속적이고 워커가 공유한다
- 단점: 테이블 추가 = 마이그레이션. 그 시점에 다른 백엔드 팀원이 모델 영역을 동시에 작업 중이라 충돌 위험이 컸다. 캐시 때문에 스키마를 건드리는 비용이 효과보다 컸다

### 대안 3 — 파일 캐시 (채택)

- 장점: 워커 수와 무관하게 하나를 공유하고 재시작 후에도 남는다. 스키마 변경 없음. 디렉터리 하나로 끝
- 단점: 동시 쓰기 시 파일 손상 가능 → 임시 파일에 쓰고 `os.replace`로 원자적 교체. 엔트리 수 상한과 TTL로 디스크 관리

## 결정

대안 3. 캐시 키는 좌표를 소수 2자리(약 1.1km)로 반올림해 만든다. 같은 농장의 체험 여러 건과 인접 농장이 한 엔트리를 공유한다.

```python
def make_key(lat, lng, radius_m, content_type_id):
    rounded_lat = round(float(lat), COORD_PRECISION)   # COORD_PRECISION = 2
    rounded_lng = round(float(lng), COORD_PRECISION)
    raw = "%s|%s|%s|%s" % (rounded_lat, rounded_lng, radius_m, content_type_id)
    return hashlib.sha1(raw.encode('utf-8')).hexdigest()
```

좌표를 반올림해도 코스가 틀리지 않는 이유: 캐시는 **후보 목록**만 공유하고, `course_builder._sorted_by_distance()`가 체험의 실제 좌표로 거리를 다시 계산한다. 격자 경계에서 수십 m 차이로 키가 갈리면 캐시를 못 나눠 쓸 뿐이고, 최악이 캐싱 전과 같은 동작이다.

빈 결과도 짧은 TTL(`TOUR_CACHE_EMPTY_TTL_SEC`)로 저장한다. 시골 농장 주변에 장소가 없을 때 매번 재조회하며 한도를 태우는 것을 막기 위해서다.

`tour_cache` 모듈은 예외를 밖으로 내보내지 않는다. 캐시가 손상되면 `None`을 돌려주고 호출부는 평소대로 KTO를 부른다.

## 결과

- 심사 시연 중 한도 소진이 재발하지 않았다.
- 측정하지 못한 것: 응답시간 개선 폭. 한도 소진 여부만 확인했고 전후 응답시간을 재지 않았다. 다시 한다면 캐시 적용 전후 p50/p95를 먼저 기록한다.
- 다시 한다면: 서버가 PythonAnywhere가 아니고 Redis를 쓸 수 있는 환경이면 Redis로 간다. 파일 캐시는 이 환경의 제약(워커 다수 · SSH만 가능 · 스키마 변경 회피)에서 나온 선택이다.
