# ADR-0002: 추천 코스는 규칙 점수로 결정하고, LLM은 "추천 이유" 문장만 생성한다

- 상태: 승인
- 결정 시점: 2026-07 (구현 커밋 `569c8e4a` AI 추천 코스, `25af59a2` 개인화 추천)
- 문서 작성일: 2026-11-09 (결정 당시 코드 주석과 회의 기록을 바탕으로 사후 기록)
- 작성자: 윤우성
- 관련 코드: `services/recommend_service.py`, `services/course_builder.py`, `services/course_reason.py`, `external/clova_api.py`

## 상황

AI 추천 코스는 사용자의 위치·조건(반려견·무장애·지역·예산 등)을 받아 체험 전후로 들를 장소를 순서대로 제안한다. 장소 후보는 체험 DB, 한국관광공사 TourAPI, 관광지 표준데이터 CSV에서 온다. 공모전 심사와 면접에서 "왜 이 장소가 이 순서로 나왔는가"를 설명할 수 있어야 했고, 시연 중 같은 조건에 다른 결과가 나오면 안 됐다.

## 결정 기준

- 재현성 (같은 입력 → 같은 코스)
- 설명 가능성 (순위의 근거를 코드와 숫자로 제시)
- 환각 방지 (없는 장소·없는 시설을 만들어내지 않음)
- 외부 LLM 비용·지연

## 검토한 대안

### 대안 1 — LLM이 장소 선정과 순서까지 생성

- 설명: 후보 목록과 조건을 프롬프트로 넘기고 LLM이 코스 JSON을 반환
- 장점: 구현이 빠르고 문장이 자연스럽다
- 단점: 같은 입력에 다른 코스가 나온다. 후보에 없는 장소를 만들거나 무장애 여부를 지어낼 수 있다. 순위 근거를 설명할 수 없다. 호출마다 지연·비용 발생

### 대안 2 — 규칙 점수로 순위·구성을 정하고, LLM은 설명 문장만 (채택)

- 설명: `score_components()`가 거리 0.5 · 특산 0.3 · 여석 0.2 가중 합과 카테고리 가점으로 순위를 정하고, `course_builder`가 거리순 정렬·예산 필터·유형별 슬롯으로 코스를 구성한다. LLM(CLOVA)에는 확정된 순위와 최대 기여 요소만 넘겨 "추천 이유" 한두 문장을 받는다
- 장점: 결정적이다. 근거가 코드에 있어 테스트할 수 있다(`tests/test_recommend_rank.py`, `tests/test_course_builder.py`). LLM이 실패해도 코스는 그대로 나온다
- 단점: 가중치를 사람이 정해야 하고, 조건이 늘수록 규칙이 늘어난다

## 결정

대안 2. 장소·순서는 코드가, 문장은 LLM이 맡는다. `services/course_builder.py` 2행 주석("장소 선정·순서는 여기서 규칙으로 정한다. LLM이 장소를 지어내지 않게 함")이 이 결정의 코드 쪽 표현이다.

## 결과

- 추천 점수 배점은 PM이 관리하는 값으로 분리했고, 가점 규칙은 "대분류당 OR·1회"로 통일했다.
- LLM 호출이 실패하거나 느려도 코스 응답은 영향을 받지 않는다.
- 트레이드오프로 가중치 조정이 수동이다. 클릭 로그 기반 세그먼트 추천(`services/segment_service.py`)으로 일부 보완했지만, 가중치 학습까지는 가지 않았다.
