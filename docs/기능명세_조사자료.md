# 1. 기능 목록

## 공통 응답 규약

- **JSON API 표준형**: `{"success": true/false, "data": ..., "error": {"code": ..., "message": ...}}` — `common/response.py`
- 다만 아래 라우트는 **표준형을 따르지 않습니다**(별도 형식):
  - `POST /check_email` → `{"exists": bool}`
  - `POST /verify_password` → `{"ok": bool}`
  - `POST /notifications/delete/<id>` → `{"success":..., "message":...}`
  - `routes/album.py` 전체 → `{"success":..., "message"/"error":...}`
  - `POST /api/farms/<id>/refresh-report` → `{"success":..., "message":...}`
- **화면 라우트**는 JSON이 아니라 `flash()` + `redirect()` 또는 템플릿 렌더로 응답합니다(HTTP 상태는 200 또는 302).

## 대분류 A. 회원

### A-1. 회원가입

| 항목 | 내용 |
|---|---|
| 대분류 | 회원 |
| 실행 주체 | 비로그인 |
| 진입점 | `GET, POST /register` → `register_page()` — `routes/auth.py` |
| 권한 | 없음. 데코레이터 없음 |
| 사용 테이블 | `user` (R: 이메일 중복확인 / W: 가입) |
| 외부 API | 없음 |
| 구현 상태 | **완료** |

**입력값**

| 필드명 | 필수 | 타입 | 검증 규칙 |
|---|---|---|---|
| `role` | 필수 | string | 필수값 일괄 검사(`all()`)에 포함 |
| `nickname` | 필수 | string | 동일 |
| `email` | 필수 | string | 동일 + DB 중복 조회. **형식(정규식) 검증 없음** |
| `password` | 필수 | string | 동일. **길이·복잡도 검증 없음** |
| `password_confirm` | 필수 | string | `password`와 문자열 일치 검사 |
| `name` | 필수 | string | 동일 |
| `phone` | 필수 | string | 동일. **형식 검증 없음** |
| `farmer_certificate_pdf` | `role='farmer'`일 때 필수 | file | 파일 존재 + 파일명 비어있지 않음 + `allowed_file()` 확장자 검사 |
| `farm_address`, `farm_size`, `profile_bio`, `birthdate` | 선택 | string | 검증 없음 |
| 프로필(연령대·성별·가족형태·관심활동·이동수단) | 선택 | string/list | `services/profile_service.clean_profile()`이 허용 코드만 통과시킴 |

**처리 흐름**

1. 폼 수신 → `password != password_confirm` 검사
2. 필수 6개 값 `all()` 검사
3. `user` 조회로 이메일 중복 확인 **(R)**
4. `generate_password_hash(password, method='pbkdf2:sha256')`
5. `clean_profile()`로 선택 프로필 정제
6. `User` 객체 생성
7. `role == 'farmer'`이면: PDF 존재·확장자 확인 → `static/uploads/farmer_cert_<email>_<uuid>.<ext>`로 저장 → `farmer_certificate_pdf` 기록, `verification_status = 'pending'`
8. `user` INSERT + commit **(W)**
9. `flash()` 후 `/login`으로 리다이렉트

**예외 처리**

| 케이스 | 응답 메시지 | 결과 |
|---|---|---|
| 비밀번호 불일치 | "비밀번호가 일치하지 않습니다." | `register.html` 재렌더(입력값 유지), 200 |
| 필수값 누락 | "모든 필수 항목을 올바르게 입력해주세요." | 재렌더, 200 |
| 이메일 중복 | "이미 가입된 이메일입니다." | 재렌더, 200 |
| 농장주 PDF 미제출 | "농장주 회원은 농업인 확인서 PDF 파일을 반드시 제출해야 합니다." | 재렌더, 200 |
| PDF 확장자 불허 | "허용되지 않는 파일 형식입니다. PDF 파일만 업로드 가능합니다." | 재렌더, 200 |
| DB 오류 | **처리 없음** (try/except 없음) | 처리되지 않은 예외 → 500 |

**정상 결과**: 302 리다이렉트 → `/login`.
참고: 농장주 분기에서 안내 `flash`가 호출된 뒤 공통 `flash`가 한 번 더 호출되어, **농장주는 안내 문구가 2개 표시됩니다.**

2. 주소 필수 검증

### D-4. 결제 승인

| 항목 | 내용 |
|---|---|
| 진입점 | `POST /api/payments/confirm` → `confirm_payment()` — `routes/payment.py` |
| 권한 | `@api_login_required` |
| 사용 테이블 | `payment`(R/W), `application`(R/W), `point_log`(W) |
| 외부 API | **토스페이먼츠 승인 API** (`POST https://api.tosspayments.com/v1/payments/confirm`, Basic 인증) |
| 구현 상태 | 완료 |

**입력값**: `paymentKey`(필수), `orderId`(필수), `amount`(필수) — 셋 중 하나라도 없으면 거부

**처리 흐름**

1. 세 파라미터 존재 확인
2. `order_id`로 `payment` 조회 → 소유자 확인
3. 이미 `status='done'`이면 중복 승인하지 않고 기존 결과 반환(멱등)
4. **금액 검증**: 클라이언트가 보낸 `amount`와 서버가 저장한 `payment.amount` 비교. 불일치 시 토스를 호출하지 않고 즉시 실패 처리 + 포인트 원복
5. `toss_service.confirm_payment(payment_key, order_id, payment.amount)` 호출 **(외부 API)**
6. 성공: `payment.payment_key`·`method`·`status='done'`·`approved_at` 저장 **(W)**
7. `application.status = '확정'`으로 전이 **(W)**
8. `point_service.earn_points_for_payment()` — **실제 결제액의 3%** 적립 **(W)**

## 2-3. 점수 계산식과 가중치 실제값

### 기본 점수 (`services/recommend_service.score_components`)

```python
distance_score     = max(0, 1 - (distance / 50))      # 50km에서 0
availability_score = (max_p - current_p) / max_p      # max_p <= 0 이면 0
specialty_score    = 1.0 if is_specialty else 0
w1, w2, w3 = 0.5, 0.3, 0.2                            # ← 함수 내부 지역변수
```

| 항목 | 가중치 | 정의 위치 |
|---|---|---|
| 거리 | **0.5** (`w1`) | `services/recommend_service.py` 함수 내부 지역변수 |
| 특산물 | **0.3** (`w2`) | 동일 |
| 잔여석 | **0.2** (`w3`) | 동일 |

> **주의**: 이 세 가중치는 `common/constants.py`가 아니라 함수 내부에 하드코딩되어 있습니다. 다른 가중치들은 모두 상수 파일에 있습니다.

### 가산점 (`common/constants.py`)

| 상수명 | 값 | 적용 조건 |
|---|---|---|
| `CATEGORY_MATCH_SCORE` | **0.3** | 충족한 대분류마다 가산(대분류당 OR·1회) |
| `CATEGORY_WEIGHTS` | **`{}`** (빈 dict) | 대분류별 가중치 override. 비어 있어 현재 전부 0.3 적용 |
| `PERSONALIZE_CROP_BOOST` | **0.4** | 과거 신청한 작물과 같은 작물 |
| `SEGMENT_TREND_BOOST` | **0.5** | 같은 성별·나이대가 많이 누른 체험 |

### 최종 계산식 (`services/personalize_service.rank_personalized`)

```
[좌표 있음] base = 0.5·distance_score + 0.3·specialty_score + 0.2·availability_score
[좌표 없음] base = 0.3·specialty_score + 0.2·availability_score      (거리 항목 제외)

score = base
      + (0.4  if 과거 신청 작물과 동일)
      + (0.3 × 충족한 대분류 개수)
      + (0.5  if 세그먼트 인기 체험)
```

## 2-4. 정규화·동점 처리·상위 N

| 항목 | 내용 |
|---|---|
| 정규화 | 각 요소를 0~1 범위로 만드는 **자연 정규화**만 사용. min-max·z-score 등 별도 정규화 **없음** |
| 점수 범위 | 이론상 상한 없음(대분류 충족 수에 따라 증가) |
| 동점 처리 | `sort(key=score, reverse=True)`만 사용. **명시적 tie-break 규칙 없음**. 파이썬 정렬이 안정 정렬이므로 동점 시 원래 조회 순서가 유지됨 |
| 상위 N | 개인화·위치 기반 모두 `limit=15` |
| 트렌드 집계 | `TREND_TOP_LIMIT` = **20** |
| 트렌드 키워드 | `TREND_KEYWORD_LIMIT` = **8** |
| 최근 본 체험 | `RECENT_VIEWS_LIMIT` = **10** |

## 2-5. 추천 사유 생성 방식

**규칙 기반입니다. LLM을 사용하지 않습니다.**

개인화 추천(`rank_personalized`)은 조건 충족 시 아래 문구를 순서대로 배열에 추가합니다.

| 조건 | 문구 |
|---|---|
| 세그먼트 인기 체험 | "나와 비슷한 분들이 많이 봤어요" |
| 과거 신청 작물과 동일 | "이전에 신청한 작물이에요" |
| 지역 특산물 일치 | "이 지역 대표 특산물이에요" |
| 좌표 있고 거리 20km 이하 | `f"가까워요(약 {거리}km)"` |

별도로 `services/recommend_reason.py`는 **점수 기여도가 가장 큰 요소 1개**를 골라 한 줄 이유를 만듭니다(목록 화면용).

## 2-6. 세그먼트·트렌드·단축버튼 산출 방식

**세그먼트 카드** (`services/segment_service.auto_segments`) — 고정 3개

| key | 제목 | 부제 |
|---|---|---|
| `peers` | `{연령대} 인기 체험` (연령대 없으면 "요즘 인기 체험") | "또래가 많이 봤어요" |
| `active` | "가볍게 즐기는 코스" | "부담 없는 하루" |
| `esg` | "ESG 친환경 코스" | "무농약·유기농" |

**세그먼트 라벨**: `{연령대}·{성별}` 형식(예: "20대·남성"). 프로필이 없으면 `None`. 성별 `other`는 라벨에서 제외.

**단축 버튼** (`segment_buttons`) — 최대 2개

1. 연령대가 있으면 `"{연령대} 놀러가기 좋은 곳"` (segment=`peers`)
2. 성별이 `male`/`female`이면 `"남자끼리/여자끼리 가기 좋은 곳"` (segment=`peers`)
3. 2개가 안 채워지면 기본 버튼으로 채움: "요즘 인기 있는 곳"(`peers`), "친환경으로 즐기기"(`esg`)

**트렌드 집계** (`services/trend_service`)

```
trending_experience_ids(gender, age_group):
  click_log ⋈ user 조인
  → target_type = 'experience'
  → gender / age_group 필터 (값이 있을 때만 적용)
  → group by target_id → count 내림차순 → 상위 20건
  → 숫자로 변환 가능한 id만 집합으로 반환
```

`trend_keywords()`는 `target_type='category'` 클릭을 집계해 상위 8개 코드·라벨·건수를 반환합니다.

# 6. 공통 처리

## 6-1. 인증·세션

| 항목 | 내용 |
|---|---|
| 인증 방식 | **Flask 세션 쿠키**. 서버측 세션 저장소·토큰(JWT 등) **없음** |
| 세션 키 | `user_id`, `nickname`, `role`, `view_mode`(농장주 이지/상세 모드) |
| 서명 키 | `app.secret_key = os.environ.get('SECRET_KEY')`. **비어 있으면 로그인·flash가 전부 500** |
| **세션 만료 정책** | **없음** — `PERMANENT_SESSION_LIFETIME`, `session.permanent`, `SESSION_COOKIE_*` 설정이 전혀 없음. Flask 기본(브라우저 종료 시 만료)을 따름 |
| 로그아웃 | `session.clear()` |
| 비밀번호 암호화 | `werkzeug.security.generate_password_hash(password, method='pbkdf2:sha256')`, 검증은 `check_password_hash` |

**권한 데코레이터** — `@login_required`는 **없습니다**.

| 데코레이터 | 위치 | 동작 |
|---|---|---|
| `@api_login_required` | `common/auth.py` | 세션에 `user_id`가 없으면 `error_response("LOGIN_REQUIRED", "로그인이 필요합니다.", 403)` |
| `@admin_required` | `common/auth.py` | 비로그인 → `/login`, **DB에서 role을 다시 조회**해 `admin`이 아니면 `/`로 리다이렉트 |
| `@farmer_required` | `routes/farm.py` | 농장주 확인 |

그 밖의 라우트는 **함수 내부에서 개별적으로 `if 'user_id' not in session`을 검사**하며, 통일된 패턴이 없습니다.
